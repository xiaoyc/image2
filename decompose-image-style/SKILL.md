# 图像风格拆解

目标是解释画面怎样成立，而非复述道具清单、猜原提示词或堆形容词。分析不得自动授权生图、发布、购买或修改第三方资料。用户要拆解时交付brief；用户另行要求生成时才把brief交给生成流程。

## 读取与证据
实际看图。每张分配稳定ID，记录可用分辨率、来源类型与完整/局部状态。网页描述是作者声明，不是图像事实。多张应逐张检查，不能只看封面或缩略图。缺失、模糊或未打开的图明确标记，禁止假装已看。

每条影响下游的判断记录：claim、evidence_type、image_ids/region、confidence、scope、counterevidence。来源类型区分：visual_observation、public_description、user_requirement、inference、unknown。视觉观察可描述年龄感、衣装和室内，但不能据此认定真实身份、关系、阶层、国籍、疾病或拍摄年代。需要叙事身份时写成用户设定或创作假设。

确切镜头焦距、光圈、ISO、色温、模型、种子、历史年份和隐藏灯位通常不可由图反推，填unknown。可建议创作性机位/光源，但标记proposed，不伪装为原作参数。

## 拆解顺序
1. **关系与视觉主次**：谁/什么先被看见，主次面积、亮度、锐度、对比、遮挡与位置如何协同？两人同尺度或近人压重造成的观看关系不同，即使对象清单相同。
2. **场景与身份衣装**：房间用途、正在发生的动作、手与物接触；服饰材质/剪裁/工艺是否与用户设定相容？“自然”不是粗旧，“富贵”不是满身金饰。未经确认不把视觉暗示转成真实身份。
3. **空间**：机位高低与距离的可见效果、桌沿/地面/墙转角/门洞、家具落地和动线。道具再多也不能代替连续空间。近景不强制展示全房，远景必须确实体现环境尺度而非仅拍全身。
4. **光照与色彩**：可见光源、受光面、阴影和反射；亮部—中间调—暗部怎样连续？分清整体色相、局部光色与材料本色。不能用“暖”“暗”“冷暖对比”代替亮度/色彩分布机制。
5. **材料与细节**：皮肤、织物、木、玻璃、金属等各自反光/粗糙度/纹理尺度；细润与磨皮、使用痕迹与粗粝、低调光泽与塑料感分别判断。写实人像约束可写“保留自然纹理，不过度磨皮”；非人像不强塞皮肤要求。
6. **行为与气氛**：把情绪落到视线、间距、手势和动作停顿，不强制微笑、愁容或统一摆拍。先确认物件的用途/房间/尺度/摆放，再谈构图配重，不为填空添加重复花瓶、香炉等。

## 多图归纳
制作逐图支持/例外矩阵。出现频繁不自动等于必要；只出现一次也可能是用户指定要保留的目标。分别列：跨图稳定机制、某分支机制、偶然题材/道具、用户新增要求。用反事实检查：换掉圆桌/性别/金布/位置后机制是否仍成立？若成立，就不要把该物锁成风格。

每条规则有 must_retain / can_vary / avoid、适用景别/场景、证据及可见验收方法。不能把“全房纵深”施加于手部特写，或把“人物同尺度”施加于用户明确要求的过肩镜头。参考本身互有差异时，保留分支，不平均成失真的唯一风格。

## 下游交接与生成前诊断
按 [references/brief-template.json](references/brief-template.json) 输出结构化brief，字段说明见 [references/contract.md](references/contract.md)。未知道的字段保留null/unknown，不能用猜测填满。若目标已有接口，保留其字段并用明确映射补充证据，不另造冲突的同名含义。

将待生成草案与brief逐项比较，而非只检查关键词是否出现：
- 对象相同但材质、光色连续性或人物权重变了，指出造成差异的具体短语及组合效应。
- 区分用户允许的新故事变化、可接受替换、核心机制丢失、模型未执行与证据不足。
- 每个问题给最小因果修改；避免只补“高级、电影、氛围”。保留不受影响的约束。
- 给出ready / needs_revision / insufficient_evidence，不以结构校验通过宣称视觉效果保证。

## 输出及验证边界
通常交付短结论、结构化brief、可迁移规则、未知项与最小验证计划。用户请求系列时建议景别覆盖，但不自动生图。
已知失败案例的回放只能称“回顾性案例验证”，不能称盲测、独立前瞻预测或未来成功率。参考 [references/amber-retrospective.md](references/amber-retrospective.md) 学习如何定位遗漏，不把琥珀风格本身推广给所有图像。
