# 拆图 → 风格 → Demo 的交接接口

本文件是接口设计及可执行的完整性检查，不是独立拆图 Skill，也不声称自动理解图片。拆图执行者必须实际看原图、细读公开 description，区分四种依据：description、visual_observation、inference、user。不能从道具清单直接生成一套风格。

## 先记录关系，再给出生成约束

对每张参考，记录实际景别与可见证据：人物相对面积/距离/姿态关系，建筑开口与地面形成的空间，主光与填光、明暗过渡和局部反射，衣料/木/瓷/皮肤的材质差异，身份与服饰工艺的匹配。看不到的部分明确未知，作者意图不冒称事实。

跨多张对照再归纳稳定规律与变量，输出每项的 retain、vary、avoid、适用景别及具体关系。保留可以是“暖中间调连续承接灯、手、衣领和木面”，不是“每张放同一盏灯”；可变可以是人物、服饰剪裁、桌形和场所；避免应指错误关系，不写成全局禁黄、禁花或强制极简。

琥珀案例提示应查：温润材质与细织衣物是否被误写成粗旧；连续琥珀中间调是否被误改成冷暖两块；人物相对视觉重量是否被过肩大背影占据。它们是当前风格审查问题，不是所有室内图的固定答案。具体来源和实际像素证据由拆解者补齐，不能仅把这段提醒当已完成观察。

## style-brief-1

见 [可填写模板](../assets/style-brief.template.json)。sources 记录公开描述链接、图像文件/页号或用户消息及实际读取状态。claims 逐条包含：

- ID、basis、source_ids、evidence；推断另写 uncertainty。
- statement：看到/读到/推断/要求的内容。
- relationship：哪些元素通过光、空间、视线、材质或身份发生关系，不能仅重复名词。
- scope：detail/near/medium/wide 的适用范围。
- retain/vary/avoid：交给风格层的具体约束与变化范围。

未读/未看不能填为观察；单张不可直接声称跨图不变量。检查器只验证声明完整、引用存在、推断标注与适用项映射，不验证像素或理解正确。尚未确定的结论保留在 unresolved，不能偷偷升级为硬规则。

Demo 入口读取 brief，将适用 claim ID 连接每张实际 prompt 的文本片段，之后图后四轴分别检查。若没达到：先定位拆解漏项、设计改写、prompt 传递遗漏、生成未遵循或审查漏项，不能一概归给模型。
