# 风格 Demo 生产入口

这是系列编排层，不再复制基础构图、光线或各套风格的全文。生成前实际读取当前项目的基础 Skill、目标风格 Skill 和适用的设计入口，记录其路径与内容摘要。已有已接受风格直接引用；新风格若有结构化拆解，接入 [style-brief 接口](references/style-brief.md)，不以物件清单替代风格关系。

## 先规划整组，再发起本次获授权的调用

- 当前用户的 Demo 主角一律使用年轻成年女性，气质、衣装与动作按风格选择，不统一套温柔甜笑；不额外指定无依据的数值年龄。此为用户本项目的展示选择，不是上游审美定律；不限制所有配角性别，也不追改历史。局部或环境辅助画面可不露主角，计划须如实标记。
- 把数量、目的、画幅、身份连续性及可用参考说明白。六张的默认建议为 1 特写、1 近景、2 中景、2 远景，覆盖可以按明确需求调整，不把六张变成永久规定。近景面部/衣料与中景互动、远景空间各有展示任务；全身可见不等于远景。
- 设计真正不同且适用该风格的情境。不要只换姿势或地名，也不要为了凑景别把不适用的场景硬塞进风格。主展示通常让面部和优势可读，辅助图可承担局部细节或环境；正面不等于微笑、直视或证件照。
- 保持已选择的风格特征，不把丰富误写成更多装饰，不把自然误写成粗旧、衰老或夸张毛孔。写实且有人物可见时，实际最终 prompt 必须含“保留自然纹理，不过度磨皮”。本入口直接复用已发布的基础皮肤检查器快照，检查原句和已识别的相反要求；有限文本匹配不能证明全部语义冲突已排除或真人感已通过。
- 先决定人物身份、服饰工艺和场所用途是否协调。物件先有合理用途和位置，再谈配重：已有同功能设施是否足够，材料/年代与身份是否相容，尺度、承重、火水条件能否成立。无道具完全可以；不默认每张左前方放花瓶，不追求左右等重。
- 将用户建议理解为目标和约束，而不是复制到每张的物件清单。修改只动请求范围；保留未要求改变的服饰、人物和环境特征。发生额外必要改变，先解释冲突，不能默默扩大。

## 连接实际生产链

1. 复制 [计划模板](assets/plan.template.json)，为每张写具体场景、动作阶段、景别用途与八域前检。`ready` 必须来自实际读卡，不能由脚本批量勾选。无适用项写原因，不强塞三层、道具或对侧锚点。
2. 使用基础/单张入口编译，或如实采用手写 prompt。手写不能重标为编译器生成。运行基础最终请求检查，保存真正要发送的工具参数 JSON，再把原文与文件 SHA256 加到计划。生成前读一遍实际 prompt，不仅看设计卡。结构化 brief 的每条适用要求须映射到实际文本片段；存在片段不证明其语义正确。
3. 明确 `style_reference`、`identity_reference`、`research_only`，只给模型传已获准使用且实际看过的我方/有权使用参考。竞品只供研究，不能作为生成输入。不将风格参考假称锁脸；纯文本跨图身份没有锁定保证。此离线清单使用显式本地参考文件，不支持无法绑定的最近对话图像指针。
4. 用脚本检查计划并冻结。每张实际调用与冻结请求一致；输出失败也保留，不偷偷修 prompt 或重抽选优。本模板每张一调用，追加修改需要新的明确范围与独立计划。调用工具的权限和费用仍单独遵守当前用户授权，本 Skill 不产生新权限。
5. 一张出来就实际查看原图，尽快交付原图及简短真实观察，不等整包。可按允许范围并行；先完成的先发。写入 [运行模板](assets/run.template.json) 的真实调用凭据、原图摘要、实际景别、四轴 QA 和原生交付回执。上传 ID 不是已经发送的证据。
6. 对照竞品时按实际景别配对。没有同景别参考就标不可直接比较；不裁切放大冒充原生特写。分别评价构图、美学/风格、brief 遵循与自然物理，指出可见证据和看不清的部分。软件检查通过与用户接受是另外两件事，不推断用户已批准。
7. 汇总覆盖矩阵、失败与尚待验证项。保留原请求、版本和图片；六个探索样本不证明统计稳定。新发现先记录为候选改进，不在冻结批次中途偷偷改规则。

## 离线命令

从项目根目录执行，路径按项目替换：

```sh
python3 produce-style-demos/scripts/validate_demo.py plan --root . --plan demo/plan.json
python3 produce-style-demos/scripts/validate_demo.py freeze --root . --plan demo/plan.json --out demo/freeze.json
python3 produce-style-demos/scripts/validate_demo.py run --root . --plan demo/plan.json --freeze demo/freeze.json --run demo/run.json
```

整组交付完成后加 `--require-delivered`：必须记录每张终态，成功图已发送，失败也已如实通知。脚本不生图、不调用 API、不执行外部项目代码。它验证已记录的文件、覆盖数量、映射、已声明调用上限与证据完整性，不证明实际看图、使用权限、历史真实性、场景合理或画面漂亮，也不能发现未记录的额外调用。详见 [字段契约](references/contract.md)、[现有项目接线与状态](references/integration.md) 及 [代码来源](references/sources.md)。

## 当前落地边界

独立 Demo 编排 Skill、模板和离线检查是本次新增；基础/风格和单张编译器是已有能力。这里提供拆图结果的交接契约，不宣称独立“拆图 Skill”或自动视觉评审器已经实现。旧奶杏、银灰、桃霞和唐风记录不回填成通过本入口；当前新入口尚未进行图像工具实测。
