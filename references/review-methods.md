# 九项前检与后检：操作方法和记录契约

这是项目自有的最小检查流程，不是外部自动审美评分器。生成前检查设计是否自洽，生成后独立看实际图；二者不能共用结论。

## 方法来源与归属

- [Photo Edit Analysis](https://github.com/pfrederiksen/photo-edit-analysis/blob/main/SKILL.md)：采用先看构图、再看影调，以及依据具体区域给可执行修改意见的思路。按本次来源核对记录，README 自述 MIT，但未获得独立 LICENSE 文件；本工程不复制其全文或代码。
- [Photo Composition Critic，固定提交 6713fc7](https://github.com/curiositech/some_claude_skills/blob/6713fc7a6451c8dee5903b98cd2063ff4cbf7317/.claude/skills/photo-composition-critic/SKILL.md) 与其 [构图理论](https://github.com/curiositech/some_claude_skills/blob/6713fc7a6451c8dee5903b98cd2063ff4cbf7317/.claude/skills/photo-composition-critic/references/composition-theory.md)：采用视觉重量、Gestalt 邻近/相似分组、非对称平衡、动线、形状节奏及类型语境。其根 MIT 通知保存在 licenses/photo-composition-critic-MIT.txt。
- 留白的具体问法、肩腰髋膝与支撑可读性、九项证据记录、前检阻断、后检失败交付规则、文件摘要绑定，以及美感和目标风格分开判断，都是本项目补充，不冒称上游现成实现。

不采用像素亮度重心替代主体理解，不按三分点或黄金点距离判合格，不给互补色等色彩类别固定分数，不采用未经本项目校准的 NIMA 阈值，不把“右上更重”等启发式写成定律，不复制或运行上游不完整脚本。

## 1. subject_weight_groups：先合并感知重量组

- 前检问题：有哪些主要组？邻近、重叠、接触、同色或同方向的元素是否先归为一组？各组依靠面积、对比、清晰边缘或内容兴趣获得多少注意力？
- 后检证据：指出实际所在区域、可见大形、边缘及组内连接。必须按成片重新分组，不能复述计划。
- 失败例：贴在腰间的书属于人物组，却又被当成另一侧独立配重；只数物件而不看组。
- 纠正方法：先重画组关系，调整姿态、物件位置、轮廓或画幅；不默认增加道具。

## 2. balance_mechanism：选对平衡方式

- 前检问题：本张使用居中凝聚、不对称平衡还是有意偏置？非主体区域承担什么？这种安排是否符合情绪和用途？
- 后检证据：结合组的面积、明暗、隔离、清晰度和方向解释关系，不能只报人物横坐标。
- 失败例：大而清楚的主体旁只有弱小色点，却直接判“已平衡”；把长线伸到另一边当作平衡成立。
- 纠正方法：调整大形、主体占比或空间任务。允许有功能的空区和单组近景，不要求两侧各放一物。

## 3. viewing_connections：观看路线与叙事关系

- 前检问题：预计先看哪里、再看哪里？手、视线、结构线或颜色如何连接？道具是被使用、被携带、交代场所，还是装饰？
- 后检证据：记录第一、第二及如适用的第三落点，说明实际连接。观察路线不是眼动测量；单锚画面无需凑足三点。
- 失败例：有手、有书，但手和书没有真正接触；道具有携带功能，却被虚报成独立构图配重；线延伸却没有有意义的落点。
- 纠正方法：让动作对象落在自然可及处，重排方向和形状；必要时简化故事而不是增加物件。

## 4. negative_space：留白有语境

- 前检问题：空区承担气氛、动作方向、距离、尺度或叙事的哪一项？删去它会改变什么？
- 后检证据：说明这块空间如何引导视线或提供呼吸，或它是否只是未组织的碎纹理残余。
- 失败例：把大片虚化区域直接命名为“高级留白”，但无法解释其与主体的关系；或认定所有空区都必须填满。
- 纠正方法：调整取景、主角位置、动线或背景大形，先确定空间用途，再决定是否添加元素。

## 5. pose_and_support：先支点，再动作

- 前检问题：站姿重心和脚在哪里？坐姿骨盆如何落在座面？手是否在自然臂展内？转身和伸手能否同时成立？
- 后检证据：指出实际手物接触、座面与骨盆关系、腿脚支撑和受力方向；没有看清的必要关系记 fail。
- 失败例：为了连接对侧物件而远够、扭身；书被托住却掩盖了完全无法判断的坐姿支撑。
- 纠正方法：把物件移近或调整身体与支点，先保证自然可达与承重，再安排造型。

## 6. proportions_and_position：比例与位置必须可读

- 前检问题：头身、肩腰髋膝的相对方向和截幅是否协调？衣料会不会把腰、胯、大腿合成连续长块？
- 后检证据：区分明确结构错误、姿态难读、布料遮挡或透视观感。指出具体位置，不无证据宣称数字拉伸或骨骼变形。
- 失败例：没有多手指就宣称解剖通过，却忽略腰胯膝转折和座面受力难读；人物纵向挤满，横向空间又无用途。
- 纠正方法：先调整姿态、衣料大形、机位和截幅，不直接压窄图片或随意缩短四肢。

## 7. shot_scale：看实际原生景别

- 前检问题：本次需要何种身体截幅、主体大小与环境比例？它是否服务本张动作和用途？
- 后检证据：记录实际头顶、身体、手脚的截幅和环境占比，比较样片时注明差异。
- 失败例：提示词写“近景”就当近景通过，或裁切中景冒充新生成特写。
- 纠正方法：在下一次已授权设计中重新选择景别或机位；不改写本次真实输出的分类证据。

## 8. light_and_color：光色服务关系

- 前检问题：主色、次色、点缀的承载物、面积、相邻颜色和位置是什么？光线会不会让无关区域最亮？
- 后检证据：指向实际面部光、轮廓、亮面及色彩呼应；区分风格色出现与综合色彩关系成立。
- 失败例：只因衣服和道具同色就判和谐，忽略面积和邻接；把柔光都当作对比不足，擅加硬光。
- 纠正方法：优先改色彩面积、位置、邻接或无关亮形，保持风格既定光质。

## 9. style_identity：美感、风格与身份分开

- 前检问题：哪些是全套不变的风格关系，哪些是本张新设计？身份参考是否误锁衣服或构图？
- 后检证据：分别记录可见的色彩、材质、光质、情绪与人物相似性，不以其中一项代替整体通过。
- 失败例：脸像、暖光和针织出现，就掩盖构图或姿态失败；风格正确被当作用户已满意。
- 纠正方法：保留已成立的风格和身份，单独修正基础或本次输入。修改或重试仍须在授权内。

## JSON 记录

顶层恰好为 schema_version、stage、target、checks。schema_version 为 "1.0"；stage 为 "before" 或 "after"；target 包含包内相对 file 和完整 sha256。checks 恰好包含上文九个英文键，各自只有 status 与 evidence。

status 仅允许 pass、fail、not_applicable。evidence 始终必填，不适用也要写具体理由。必要关系无法确认记 fail，不可用 not_applicable 代替；九项不能全部不适用。

before 的 target 指向本次 inputs/series-NNN.json；after 指向实际输出图片。证据是真实设计判断或看图判断，脚本不能验证文字真假，也不替视觉模型或用户评分。

## 执行与退出状态

```bash
python3 -B validate_review.py --review examples/series-004-r3-before.json --stage before
python3 -B compose_prompt.py --base base-image-production/base.json --style styles/apricot-colonnade.json --input inputs/series-004-r3.json --edit inputs/series-004-r3-edit.json --review examples/series-004-r3-before.json --out build/r3-preview
python3 -B validate_review.py --review examples/series-004-r3-after.json --stage after
```

- 记录结构或文件摘要错误：校验命令退出 2。
- 前检任一 fail：退出 3，编译器也拒绝组装；改设计并更新证据后再继续。
- 前检全部适用项 pass：记录声明设计通过，但不代表脚本自动评美，也不新增生成授权。
- 后检结构完整但有 fail：校验命令退出 0，输出 declared_outcome="fail"。这里的 0 仅表示记录有效，不表示成片通过；按用户要求交付时必须明确失败项，不自动重试。

001/002的失败结论见examples/README.md。原始审计工程的真实请求不回写；本公开仓库只提供经整理的回归案例，不把新规则伪装成旧调用已采用的方法。

## 0.3.2环境叙事校准

前检先确定本张是否需要生活环境。需要时说明次级活动或使用痕迹为何可读、如何低于主体；不需要则不补人物/物件。后检在negative_space与viewing_connections证据里记录实际层次和用途，不能仅确认物件出现。面积须与透明度、内容兴趣、对比及边缘密度合看；可优化或正常出框不自动fail。003/004补记见../review-addendum-20261022/CALIBRATION.md。r3实际证据见../examples/series-004-r3-QA.md，r2是保留环境的动作修订输入。
